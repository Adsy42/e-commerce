# Making a Shopify change

1. Select the store and read its instructions, manifest, and relevant decision history.
2. Confirm the runtime boundary and the connection's actual store identity. Do not rely on a name shown in the sidebar or an agent instruction.
3. State the problem, baseline, proposed change, business effect, and affected surfaces.
4. Make a draft or development-theme change where supported. Keep production untouched until the action is authorized.
5. Validate the affected journey. For a theme change, check relevant pages, mobile layout, accessibility, navigation, cart behavior, console errors, and performance. Check checkout only through supported Shopify test flows.
6. Record the exact target, validation evidence, rollback, and any remaining uncertainty in the store's operations directory.
7. Publish, send, or apply only within the user's granted scope. Verify the resulting state and record the outcome without customer-level data.

Use `templates/change-record.md` for substantial changes. A passing file validator is not a functional Shopify test.
